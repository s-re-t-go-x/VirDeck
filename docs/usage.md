# 使用指南

## 启动与环境

编译完成后运行 `dist/VirDeck.exe`。Windows 的虚拟化和 WHPX 状态可在“镜像与环境”中查看；如提示未启用 Windows Hypervisor Platform，按提示启用并重启电脑。

首次启动缺少工具或镜像时会打开环境管理。运行目录应使用有读写权限的英文路径；名称是否包含中文与运行目录路径是两回事，实例显示名称支持中文。

## 工具与系统镜像

1. 如需下载代理，先在“设置”中填写 HTTP / SOCKS5 代理并保存。
2. 在“镜像与环境 → 运行环境”下载补齐 adb、emulator、scrcpy，或为组件导入本地 `.zip`。
3. 在“系统镜像”中下载、离线导入或同步官方列表。Beta / 预览项被过滤，已知 API 会显示安卓版本号。
4. 点击星星收藏并置顶，可添加、编辑备注。初始默认收藏 Android 11 Google Play，备注为“Gmail / Facebook / WhatsApp / Instagram / Chrome 首选”；用户后续修改会保留。

数据目录与 AVD 目录旁可点击“打开目录”。下载压缩包保留在 `VirDeckData/downloads/`，用于复用或断点续传。

## 创建、编辑与批量操作

- 新建实例支持中文名称，批量时作为名称前缀。默认创建 1 个、内存 2048 MB、CPU 2 核、720p、后台运行；实际初始值以编译进程序的默认数据为准。
- 新建镜像下拉框中，“✓ 已安装”项可直接使用并排在前面。
- 选中单个实例，在详情区“更多操作 → 编辑”中修改名称、内存、CPU、代理和运行模式；窄窗口操作条直接显示“编辑”按钮。名称立即生效，其余配置在下次启动时应用。系统镜像保持只读。
- 中文显示名称与内部 AVD 名称分开保存；改名不移动目录，不重建实例。
- 勾选设备或使用 Ctrl / Shift 选择多个实例，再按状态执行批量启动、停止、安装 APK、Shell 命令等操作。
- “投屏”通过 scrcpy 打开设备画面；“克隆”要求源实例已停止。
- 删除实例会清除该实例的应用及本地数据，确认前会列出目标。失败项会保留，便于检查和重试。

下载代理控制 SDK / 镜像下载；实例代理在编辑窗口或代理操作中设置，两者独立。运行中修改实例代理会提示重启生效。

## 多窗口投屏排版

先为运行中的实例打开“投屏”，再点击工作台顶部“投屏排版”（窄窗口显示“排版”）：

- 范围可选全部已打开投屏，或打开面板时选中的实例；未打开的投屏不会被启动。
- 大小可选“当前大小 / 小 / 中 / 大”。“当前大小”以范围内首个实例的画面高度为准，各窗口保持自身比例。
- 选择“以窗口为基准”，再选择一个已调好大小和位置的投屏。基准窗口保持原位，其他窗口按它的画面高度向周围排列；目标显示器随基准窗口确定。
- 所有模式均不再缩小窗口来强行塞满屏幕：能放几个放几个，放不下的窗口保持原位，提示“桌面空间不足”。排位避开任务栏及范围外已有投屏。
- “保存当前布局”记录当前范围内已打开窗口的位置、大小与显示器，再次保存会替换之前的记录。“恢复已存布局”只恢复当前范围内已打开且有记录的窗口；显示器断开、尺寸或位置已无法放入工作区时，跳过并提示。
- 勾选“新投屏自动补位”，完成一次排版后，新打开的投屏会沿用上次排版的大小与显示器寻找空位；已有窗口保持不动，无空位时新窗口保持打开时的位置并提示。再次点击已有投屏只会唤起，不会补位。

偏好保存在 `VirDeckData/config/settings.json`，一份已保存布局位于 `VirDeckData/config/screen_layout.json`。只保存少量坐标和尺寸，不保存画面。恢复布局按当前显示器缩放换算，布局配置可随数据目录迁移。

仅管理本程序对应 scrcpy 组件打开且带实例标识的窗口。升级前已经打开的旧投屏，可重新点一次该实例的“投屏”后纳入排版。若实例重启后提示旧投屏连接已变化，先关闭旧窗口再打开。

## 空间清理

进入“镜像与环境 → 空间清理”，先扫描，再按需选择：

| 清理项 | 范围与影响 |
| --- | --- |
| 下载压缩包 | `downloads/` 下已完成的 `.zip`；重新安装时可能需重新下载 |
| 未完成下载 | `.part` / `.meta`；下次下载从头开始 |
| AVD 缓存分区 | 已停止实例的 `cache.img` 和 `cache.img.qcow2` |

检测到模拟器运行或无法确认 ADB 状态时，AVD 清理禁用。清理不会删除用户磁盘、SD 卡、应用或账号数据，不做磁盘压缩。界面显示逻辑文件大小，稀疏文件的实际磁盘占用可能更小。

## 日志

“任务与日志”保留最近 500 条内存日志，退出后不保留。模拟器输出也在内存中收集，目前不自动写入日志文件。“清空日志”只清空当前界面内容。

## 数据位置与迁移

默认读取可执行文件旁的 `VirDeckData/`，直接从项目 `dist/` 运行时即为 `dist/VirDeckData/`：

```text
VirDeckData/
├── config/      # settings.json、instances.json、images_catalog.json
├── .android/    # 隔离的模拟器配置与密钥
├── avd/         # 实例磁盘和配置
├── sdk/         # 工具与系统镜像
├── scrcpy/      # 投屏组件
└── downloads/   # 下载包和断点文件
```

关闭程序和所有实例后，可整体迁移可执行文件与 `VirDeckData/`。启动时会修复 AVD `.ini` 中的绝对路径。也可通过 `VIRDECK_DATA_DIR` 指定其他位置；整理项目、重新编译或删除旧 ZIP 不应删除运行数据。

## 默认配置与产品信息

源码项目的 [config/defaults.json](../config/defaults.json) 仅用于编译前修改，编译时内嵌到程序，用户无需携带此文件。运行时不会读取任何外部 `defaults.json`。首次运行自动建立 `VirDeckData/config/` 下的 `settings.json`、`instances.json`、`images_catalog.json`；之后使用这些用户配置，已保存的设置、实例和收藏不会被初始值覆盖。开发者修改默认数据后需重新编译。

产品名、版本、文件描述等位于 [assets/product.json](../assets/product.json)。修改后运行 `go generate ./assets`，再按根目录 README 的两条命令重新编译。
