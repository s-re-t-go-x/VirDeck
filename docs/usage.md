## 1. 启动与环境准备

运行桌面端程序（Windows 为 `VirDeck.exe`，macOS 为 `VirDeck.app`，Linux 为 `VirDeck`）。首次启动缺少必要组件或系统镜像时，会自动弹出 **「镜像与环境管理」** 引导窗口。

- **路径与权限要求**：
  - **Windows**：程序与数据目录（默认同级 `VirDeckData/`）必须位于**纯英文/数字（ASCII）且有读写权限**的路径下（例如 `D:\VirDeck`），因为 Windows 版官方 Android Emulator 底层不支持含中文字符的路径。
  - **macOS / Linux**：支持 UTF-8 路径；macOS 从 `.app` 应用包运行时，默认数据目录自动位于 `~/Library/Application Support/VirDeck`（也可通过环境变量 `VIRDECK_DATA_DIR` 自定义）。
  - **注意**：在任何系统下，软件内创建的**实例显示名称和分组名称均完全支持中文**。
- **硬件加速**：
  - **Windows (WHPX)**：Android Emulator 依赖 Windows Hypervisor Platform。若检测提示未启用，请在「启用或关闭 Windows 功能」中勾选 **「Windows 虚拟机监控程序平台」**（及「虚拟机平台」），确定并重启电脑。
  - **macOS (Hypervisor.framework)**：依赖 macOS 原生 `Hypervisor.framework`（Apple Silicon 需使用 `arm64-v8a` 镜像，Intel Mac 使用 `x86_64` 镜像）。
  - **Linux (KVM)**：需开启 BIOS/UEFI 虚拟化并确保当前用户对 `/dev/kvm` 具备读写权限（可将当前用户加入 `kvm` 组后重新登录）。

## 2. 运行工具与系统镜像管理

### 下载代理设置
若所处网络无法直连 `dl.google.com` 或 GitHub Releases，请先点击左侧导航 **「设置 → 常规」**，填写 HTTP 或 SOCKS5 下载代理（如 `http://127.0.0.1:7890`）并点击「保存全局设置」。
> **说明**：此处的「下载代理」仅用于软件下载 SDK 工具和系统镜像，与单个安卓实例的联网代理互相独立。

### 补齐运行工具 (`emulator` / `adb` / `scrcpy`)
打开 **「镜像与环境 → 运行环境」**：
- 点击底部 **「一键下载补齐缺失工具」**，确认 Google Android SDK 许可协议后，程序会自动按当前宿主操作系统与 CPU 架构下载并校验解压缺失的组件。
- 若处于内网或离线环境，可点击各组件右侧的 **「导入 .zip」** 选择已下载好的官方压缩包（支持 `.zip`、`.tar.gz`、`.tgz`）离线安装。
- 点击底部「数据目录」或「AVD 目录」右侧的 **「打开目录」** 可在系统文件管理器中直接查看文件。

### 管理系统镜像
打开 **「镜像与环境 → 系统镜像」**：
- **架构自动适配与默认收藏**：系统会自动筛选与当前芯片架构兼容的镜像（Apple Silicon `arm64` 显示 `arm64-v8a` 镜像，默认收藏 `Android 11 Google Play · ARM64`；Windows / Intel Mac / Linux x64 显示 `x86_64` 镜像，Windows 额外支持 32 位 `x86` 镜像，默认收藏 `Android 11`、`Android 9 (64位)` 与 `Android 7.1 (32位)`）。点击镜像左侧的星标 `☆` 可将其收藏并置顶（`★`），收藏后可点击「备注」添加用途说明。
- **同步官方列表**：点击右上角 **「同步官方列表」** 可从 Google 官方仓库动态拉取所有适配当前架构的正式版镜像（自动过滤 Beta / 预览版，并标注对应 Android 版本号）。
- **下载与离线导入**：对未安装的镜像点击 **「下载安装」**（支持断点续传与 SHA-1 校验），或点击 **「导入 .zip」** 导入本地镜像包。
- **自定义镜像**：点击 **「+ 自定义镜像」** 可手动添加第三方或企业内部镜像条目。
- **防误删保护**：已安装的镜像可点击「删除镜像」释放空间；但若有实例正在使用该镜像，系统会拒绝删除以保护实例数据。

## 3. 实例创建、编辑与批量操作

### 新建实例
点击工作台右上角 **「+ 新建实例」**：
- **所属分组**：默认继承当前工作台正在筛选的分组，也可直接切换为其他分组或未分组。
- **实例名称 / 批量前缀**：支持中文。创建数量为 `1` 时直接使用该名称（若重名则自动加 `_01` 等后缀）；批量创建时自动按 `前缀_01`、`前缀_02` 编号。
- **系统镜像**：下拉框中标注 `✓ 已安装` 的镜像排在最前，可直接选用。
- **硬件与分辨率**：默认 `2048 MB` 内存、`2` 核 CPU、`720p (720×1280)` 分辨率、默认开启后台无头运行（`-no-window -no-snapshot`）。

### 编辑单个实例
选中单个实例，在右侧详情栏点击 **「更多操作 → 编辑」**（窄窗口下在列表上方操作条直接点击 **「编辑」**）：
- 可修改实例显示名称、内存、CPU 核数、HTTP 代理与运行模式（后台无窗口 / 独立窗口）。
- **生效时机**：显示名称修改后**立即生效**（底层 AVD 目录名保持不变，无需移动文件或重建实例）；内存、CPU、代理与运行模式在**下次启动实例时生效**。运行中修改代理会显示醒目的「待重启生效」标记。

### 批量选择与状态感知操作
- **选择方式**：点击列表左侧复选框、使用表头「全选 / 选择 → 仅选运行中」，或在列表中使用 `Ctrl + 点击`、`Shift + 点击` 多选。
- **智能状态过滤**：
  - 当多选的实例状态不一致（例如选中 3 台实例，其中 2 台运行中、1 台已停止）时，操作按钮会显示可执行数量（如 `投屏 (2/3)`），点击后弹窗确认 **「仅操作可用的 2 台」**，避免因单台实例状态不符而阻断整批任务。
  - **启动 / 停止**：动态分配 `[5554..5584]` 偶数端口，启动期间实时展示已等待秒数（`◐ 启动中 · 18s`）与引导阶段提示；停机时先通过 `adb emu kill` 优雅刷盘退出，超时自动强制清理整个模拟器进程树。
  - **投屏**：为运行中的实例拉起独立 `scrcpy` 窗口；关闭投屏窗口不会停止后台运行的安卓实例。
  - **安装 APK**：选择本地 `.apk` 文件后并发安装到所选运行中实例。
  - **批量命令**：并发向所选运行中实例执行 `adb shell` 命令（如 `getprop ro.build.version.release`），输出结果记录在底部「运行日志」中。
  - **克隆**：仅对单台**已停止**实例开放，默认继承源实例的所属分组（注意：已开机登录过账号的母版克隆后会共享 `ANDROID_ID` 与 `GSF ID`，日常多开建议优先使用「新建实例」）。
  - **删除**：弹窗列出目标实例名称并二次确认，运行中的实例会先停止再删除；若某台删除失败会保留选中状态以便重试。

## 4. 分组管理与筛选

- **按分组筛选**：工作台列表上方提供分组筛选下拉框，可切换 **「全部分组」**、**「未分组」** 或自定义分组。各选项显示组内总实例数，不受搜索与状态筛选影响。分组筛选与下方的状态标签页（全部 / 运行中 / 已停止 / 异常）及右侧搜索框实时联动，批量操作仅作用于当前筛选视图下选中的实例。
- **列表与详情栏归属展示**：在「全部分组」视图下，实例列表行副标题会将所属分组与系统镜像同行展示（如 `工作 · Android 11 · Play`）；右侧详情栏头部状态徽章旁提供轻量分组胶囊菜单（`分组: xxx ▾`），可一键切换归属或新建分组并移入。
- **管理分组**：点击 **「管理分组」**，上方列表展示已有分组及成员数，可直接重命名或删除；下方提供独立的新建分组输入区。删除分组只会将该组内的实例移回「未分组」，**绝不会删除实例或清除安卓数据**。
- **批量移动实例到分组**：在列表中勾选一个或多个实例后，点击顶部 **「移动到分组」** 菜单即可批量调整归属，或选择「+ 新建分组并移入」一步完成。分组关系保存在 `VirDeckData/config/groups.json`。

## 5. 多窗口投屏排版

当同时打开多个实例的 `scrcpy` 投屏窗口时，点击工作台顶部 **「投屏排版」**（窄窗口显示「排版」）：

- **排列范围**：可选「全部已打开投屏」或「仅选中实例」（不会自动启动未打开的投屏）。
- **窗口大小模式**：
  - **当前大小**：以范围内首个投屏窗口的当前画面高度为准，其余窗口按各自宽高比对齐排列。
  - **小 / 中 / 大**：按预设高度（默认 `360` / `540` / `720` 像素）等比缩放排列。
  - **以窗口为基准**：指定一个已手动调好位置与大小的投屏窗口作为基准，基准窗口保持原位不动，其余窗口沿用其高度在同显示器空余位置排列。
- **不强行压缩画面**：所有模式均保持画面原始比例，能放几个放几个，空间不足放不下的窗口保持原位并提示「桌面空间不足」，自动避开任务栏 / Dock / 菜单栏及范围外已有的投屏窗口。
- **保存与恢复布局**：点击 **「保存当前布局」** 将当前已打开投屏的位置、大小与所在显示器记录到 `VirDeckData/config/screen_layout.json`；后续点击 **「恢复已存布局」** 即可按显示器缩放比例还原。
- **新投屏自动补位**：勾选 **「新投屏自动补位」** 并完成一次排版后，新打开的投屏窗口会自动按上次排版的尺寸在目标显示器寻找空位放置，不打乱已有窗口；再次点击已打开投屏的实例只会激活窗口，不会触发重新补位。
- **平台说明**：Windows（Win32）与 macOS（CoreGraphics + Accessibility API，需在系统设置中授予「辅助功能」权限）支持完整的已打开窗口动态排列与布局保存/恢复；Linux 环境支持通过 `scrcpy` 启动坐标参数（如 CLI `screen -x -y -width -height`）指定位置并在重开投屏时保持启动坐标。

## 6. 投屏参数与声音控制

投屏画面参数与声音转发支持 **「全局默认 + 单实例覆盖」** 两级控制，修改参数仅控制 `scrcpy` 编码与转发，**不修改安卓内部屏幕分辨率、CPU 或内存，也无需重启安卓模拟器**。

- **全局设置**：点击 **「设置 → 投屏与声音」**，统一配置：
  - **投屏帧率**：范围 `5–240 FPS`（步进 `5`，默认 `60 FPS`）。多开挂机时调低帧率（如 `15 FPS`）可显著降低宿主 CPU/GPU 占用。
  - **投屏最长边**：范围 `320–8192 像素`（步进 `160`，默认 `1280 像素`）。按比例缩放编码尺寸，不会放大较小画面。
  - **投屏码率**：范围 `1–100 Mbps`（默认 `8 Mbps`）。
  - **声音**：默认关闭（静音）。勾选「播放安卓声音」后通过 `scrcpy`（默认使用高兼容性的 `AAC` 编码）转发安卓内部音频。
- **一键预设**：全局与实例表单顶部均提供「省资源多开」（15 FPS / 960 px / 2 Mbps）、「均衡日常」（60 FPS / 1280 px / 8 Mbps）、「高清流畅」（60 FPS / 1920 px / 16 Mbps）。点击后仍可微调，预设保留当前声音选择。
- **快捷声音与批量设置**：详情栏「设备配置」中单行展示「投屏配置」摘要（默认或独立配置、帧率、清晰度与声音状态），顶部主操作栏旁提供紧凑的「静音 / 有声」按钮一键切换；若切换后参数与全局设置一致会自动恢复跟随全局，并自动重开已有投屏（原本关闭的投屏保持关闭）。多选后点击「投屏设置」可统一设置预设或恢复跟随全局；配置不一致时需先明确选择统一方式。
- **全局保存后重开**：全局「投屏与声音」中点击「保存并重开已打开投屏」，只重开跟随全局的已有投屏，跳过独立配置与正在执行任务的实例；失败原因见底部任务与日志。
- **单实例覆盖与即时生效**：
  - 选中单个实例，打开 **「投屏设置」**（详情栏「更多操作 → 投屏设置」或操作条「投屏设置」）。
  - 取消勾选「跟随全局设置」即可为该实例单独设置帧率、清晰度、码率与声音；重新勾选则恢复继承全局设置。
  - 点击 **「保存并重新投屏」** 可在不重启安卓系统的情况下自动重开该实例的投屏窗口，并尽量保持原有的窗口位置与大小。
- **声音注意事项**：音频转发需要 **Android 11 (API 30) 及以上**系统镜像（Android 9 / 7.1 镜像不支持音频转发），且安卓系统内部媒体音量未静音；Android 11 首次启动音频采集时设备需处于解锁状态。模拟器进程固定携带 `-no-audio` 抑制宿主直出声音，确保关闭投屏声音时彻底静音。

## 7. 电脑与安卓文件收发

选中运行中的实例后，点击操作条的 **「文件传输」** 或详情栏 **「更多操作 → 文件传输」**：

- **发送到 Android（支持单台或多台并发发送）**：
  - 点击「选择本地文件」可多选本地文件。
  - 默认接收目录为 `/sdcard/Download/VirDeck/`（仅允许 `/sdcard` 或 `/storage/emulated/0` 共享存储路径）。每次发送会在目标目录下建立带时间戳与唯一后缀的独立子目录，并对同名文件自动编号，防止静默覆盖已有文件；完成后自动通知 Android 刷新相册，刷新失败会单独记录日志。弹窗列出已选文件名，支持清空或重新选择，完成状态显示实际目标路径。
- **接收到电脑（单实例导出）**：
  - 选择接收来源实例，可通过「常用 Android 文件夹」快速填入下载（`/sdcard/Download`）、图片（`/sdcard/Pictures`）、相机（`/sdcard/DCIM`）、文档或音乐路径，也可输入具体文件或子目录路径。
  - 切换到接收模式、切换常用目录或来源实例时会自动读取远程目录列表，也可点击「读取目录」手动刷新。点击文件选中具体接收目标，点击文件夹进入子目录，并可通过「上一级」返回；也可直接接收整个目录。
  - 本地接收目录首次默认使用用户目录下的 `Downloads`，本次运行期间记住上次填写的位置。点击「接收文件」后程序创建 `VirDeck-export-xxxx` 独立导出目录，完成状态显示实际路径，并提供 **「打开接收文件夹」** 按钮。
- **安全校验与中断处理**：
  - 支持含中文、空格及特殊字符的文件名。
  - 接收前会自动扫描远程目录清单：若包含符号链接、非法字符（如 `:`、`*`、`?`、末尾点号/空格、保留设备名）或大小写不敏感重名文件，会在拉取前明确报错拦截。
  - 传输期间可随时点击 **「取消传输」**。

## 8. 空间清理

打开 **「镜像与环境 → 空间清理」**，点击 **「扫描可清理文件」** 后可按需勾选清理：

| 清理项 | 清理范围 | 影响说明 |
| :--- | :--- | :--- |
| **下载压缩包** | `downloads/` 下已完成的 `.zip`、`.tar.gz`、`.tgz` | 不影响已安装的组件和镜像；日后若需重装则需重新下载 |
| **未完成下载** | `downloads/` 下的 `.part` 与 `.meta` | 清除中断的下载缓存，下次下载将从头开始 |
| **AVD 缓存分区** | 已停止实例目录下的 `cache.img` 与 `cache.img.qcow2` | 仅清理临时缓存分区，**不删除用户数据 (`userdata`)、SD 卡、已安装应用或登录状态** |

> **安全保护**：当检测到有模拟器正在运行或无法通过 ADB 确认运行状态时，「AVD 缓存分区」清理项会自动禁用，防止损坏运行中实例。

## 9. 任务与运行日志

窗口底部常驻任务状态栏，点击右侧 **「任务与日志」** 可展开面板：

- **异常原因直达**：实例处于 `✖ 异常` 状态时，列表行直接展示单行错误摘要并提供完整错误悬浮提示（`Tooltip`）；右侧详情栏首屏顶部展示「最近错误」及 **「复制错误」** 按钮。任何窗口宽度下任务失败均可在底部状态栏直接点击 **「查看失败原因」**。
- **任务列表**：展示近期批量任务的执行进度、成功数与失败数。对于失败的任务项，直接显示每台实例的具体失败原因，并支持点击 **「重试失败项」**（自动跳过已删除或当前状态不适用的实例）。
- **运行日志**：保留最近 500 条带时间戳的内存日志，包含环境自检、启动引导、ADB 命令输出、文件收发结果及投屏异常退出原因。支持点击 **「复制日志」** 一键写入系统剪贴板或点击「清空日志」清空当前面板。

## 11. 数据目录结构与迁移

默认情况下，便携运行的所有数据保存在可执行文件同级的 `VirDeckData/` 目录（macOS 从 `VirDeck.app` 启动时默认位于 `~/Library/Application Support/VirDeck`）：

- `config/settings.json`：全局设置（下载代理、最大并发数、投屏默认参数与单实例覆盖、排版偏好、许可协议确认状态）
- `config/instances.json`：实例注册表（原子写临时文件再重命名，防崩溃损坏）
- `config/groups.json`：实例分组定义与成员映射
- `config/screen_layout.json`：已保存的多窗口投屏坐标与显示器布局
- `config/images_catalog.json`：系统镜像目录缓存、收藏与备注

**迁移方法**：确保所有安卓实例已停止且 VirDeck 已退出后，直接将程序与数据目录整体移动或复制到新位置（Windows 下需为纯英文路径）即可。启动时程序会自动扫描 `avd/*.ini` 并将 `path=` 与 `path.rel=` 修正为当前路径。

## 12. 常见问题排查 (FAQ)

1. **启动实例报错硬件加速（WHPX / Hypervisor.framework / KVM）不可用？**
   - **Windows**：以管理员身份打开 PowerShell 运行 `dism.exe /online /enable-feature /featurename:HypervisorPlatform /all`，完成后**重启电脑**，并确认 BIOS 已开启虚拟化。
   - **macOS**：确认 `sysctl -n kern.hv_support` 输出为 `1`，并使用与芯片架构匹配的系统镜像（Apple Silicon 使用 `arm64-v8a`，Intel Mac 使用 `x86_64`）。
   - **Linux**：确认已加载 `kvm` 模块且当前用户对 `/dev/kvm` 有读写权限（`sudo usermod -aG kvm $USER` 后重新登录）。
2. **Windows 下提示路径包含非 ASCII 字符或无写入权限？**
   - Windows 版官方 `emulator.exe` 在中文路径（如 `C:\Users\张三\桌面\VirDeck`）下无法正常挂载镜像，请将整个目录移至如 `D:\VirDeck` 等纯英文路径，并避免放在需要管理员权限的 `C:\Program Files` 下。
3. **macOS 下点击「投屏排版」提示需要辅助功能权限？**
   - macOS 管理其他应用的窗口位置与尺寸需要 Accessibility 权限。请打开「系统设置 → 隐私与安全性 → 辅助功能」，勾选 `VirDeck`（若从终端运行则勾选对应终端应用），授权后重新打开即可。
4. **开启了投屏声音但听不到声音？**
   - 请确认：(1) 实例使用的是 **Android 11 (API 30) 或更高版本**的系统镜像；(2) 安卓系统内部的媒体音量已调高且未静音；(3) 已通过详情栏顶部「静音 / 有声」按钮或「保存并重新投屏」重开投屏窗口。
5. **修改了实例代理或内存/CPU，为什么没有立即变化？**
   - 模拟器硬件参数与 `-http-proxy` 均为进程启动参数，运行中修改后会标注「待重启生效」，将该实例「停止」后再「启动」即可应用。
