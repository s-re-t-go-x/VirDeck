## 1. 界面导航与环境准备

桌面端采用 **左侧导航栏 + 右侧圆角主工作区** 的 5 大主视图结构（窄窗口自动切换顶部下拉菜单）：

- **实例工作台**（含内嵌分组树与右侧详情栏）
- **文件传输**（发送队列 + 远端 `/sdcard` 双栏浏览）
- **镜像与环境**（系统镜像 / 运行环境 / 空间清理）
- **运行日志**（全页筛选、搜索与复制）
- **设置**（常规与下载 / 投屏与声音）
- **使用帮助**：点击左侧栏底部「使用帮助」弹出快速说明。

首次启动检测到缺少核心工具或路径异常时，会弹出轻量 **「检测到运行环境不完整」** 决策卡，或在工作台顶部展示环境提示条，可一键补齐基础工具或前往环境页处理。

- **路径与权限要求**：
  - **Windows**：官方 `emulator.exe` 底层不支持含中文/非 ASCII 字符的目录。若程序放在中文路径下，VirDeck 会优先尝试通过 `8.3` 短路径或非管理员 NTFS 目录联接透明映射；若受系统策略限制未能映射，可在决策卡或「运行环境」页点击 **「一键改用纯英文数据目录」**（或「自选纯英文目录」）持久化切换至纯英文路径，重启生效。
  - **macOS / Linux**：原生支持 UTF-8 路径；macOS 从 `.app` 应用包运行时，默认数据目录位于 `~/Library/Application Support/VirDeck`（也可通过环境变量 `VIRDECK_DATA_DIR` 自定义）。
  - **注意**：任何系统下创建的**实例显示名称、备注和分组名称均完全支持中文**。
- **硬件加速**：
  - **Windows (WHPX)**：请在「启用或关闭 Windows 功能」中勾选 **「Windows 虚拟机监控程序平台」**，确定并重启电脑。
  - **macOS (Hypervisor.framework)**：依赖 macOS 原生虚拟化（Apple Silicon 使用 `arm64-v8a` 镜像，Intel Mac 使用 `x86_64` 镜像）。
  - **Linux (KVM)**：需开启 BIOS/UEFI 虚拟化并确保当前用户对 `/dev/kvm` 具备读写权限（可将当前用户加入 `kvm` 组后重新登录）。

## 2. 运行工具、系统镜像与空间清理

### 全局设置（「设置」页面）
- **常规与下载**：
  - **下载代理**：填写 HTTP 或 SOCKS5 代理（如 `http://127.0.0.1:7890`），**仅用于下载 SDK 组件与系统镜像**，与单个实例联网代理独立。
  - **最大运行实例数**：默认 `8`，控制并发启动与同时运行的实例上限（`1–16`）。
  - **下载清理**：勾选「安装成功后自动删除下载压缩包」后，在线下载的组件或镜像在安装完成后自动清理 `downloads/` 下对应压缩包（不删除手动导入的本地包）。
- **投屏与声音**：集中配置全局默认投屏帧率、清晰度、码率、声音开关及三档场景预设，支持 **「保存并重开已打开投屏」**。

### 补齐运行工具（「镜像与环境 → 运行环境」）
- 点击右上角 **「一键下载补齐缺失工具」**，确认 Google Android SDK 许可协议后，自动按宿主 OS 与 CPU 架构下载并校验解压缺失的 `emulator`、`adb` 与 `scrcpy`。
- 离线环境可点击各组件右侧 **「导入 .zip」** 导入已下载的 `.zip` / `.tar.gz` / `.tgz` 安装包。
- 页面底部展示数据目录、映射路径（如有）与 AVD 目录，点击 **「打开目录」** 可在系统文件管理器中打开。

### 管理系统镜像（「镜像与环境 → 系统镜像」）
- **筛选与搜索**：顶部提供 `全部`、`已安装`、`已收藏`、`支持 ARM 应用` 四个筛选标签与关键词搜索框。
- **架构匹配与默认收藏**：
  - x86_64 宿主默认置顶收藏 `Android 11 (API 30)`、`Android 14 (API 34)`、`Android 9 (API 28)` 与 `Android 7.1 (API 25 · 32位)`。
  - Apple Silicon (`arm64`) 宿主默认置顶收藏 `Android 11` 与 `Android 14 Google Play · ARM64`。
  - 点击星标 `☆` 可收藏并置顶（`★`），收藏后可点击「备注」记录用途。
- **ARM 应用兼容与校验和警示**：
  - 内置 `libndk_translation` 的 Android 11+ Google 镜像标注绿色 **「✓ 支持 ARM 转译」**，ARM64 镜像标注 **「✓ 原生 ARM64」**。
  - 未提供 SHA-256 / SHA-1 校验和的自定义或非官方条目会显示琥珀色 **「⚠ 未提供安全校验和」** 警示角标；官方仓库与内置 `scrcpy` 预设均启用校验和校验。
- **同步、下载、导入与保护**：点击 **「同步官方列表」** 从 Google 仓库拉取最新正式版镜像；支持在线断点续传 **「下载安装」**、本地 **「导入 .zip」** 与 **「+ 自定义镜像」**；已有实例引用的镜像受保护禁止删除。

### 空间清理（「镜像与环境 → 空间清理」）
点击 **「扫描可清理文件」** 后可按需勾选清理：

| 清理项 | 清理范围 | 影响说明 |
| :--- | :--- | :--- |
| **下载压缩包** | `downloads/` 下已完成的 `.zip`、`.tar.gz`、`.tgz` | 不影响已安装组件与镜像；日后重装需重新下载 |
| **未完成下载** | `downloads/` 下的 `.part` 与 `.meta` | 清除中断缓存，下次下载将从头开始 |
| **AVD 缓存分区** | 已停止实例目录下的 `cache.img` 与 `cache.img.qcow2` | 仅清临时缓存，**不删除 `userdata`、应用或账号数据**（有实例运行时自动禁用保护） |

## 3. 实例创建、编辑与工作台操作

### 新建实例
点击工作台右上角 **「+ 新建实例」**（也可点击底部 **「从备份还原…」**）：
- **所属分组**：默认继承当前工作台选中的分组，可随时切换。
- **实例名称 / 批量前缀**：支持中文。创建数量为 `1` 时使用该名称（重名自动追加 `_01` 等后缀）；批量创建自动编号。
- **系统镜像**：已安装镜像带 `✓ 已安装` 前缀排在最前。
- **分辨率与硬件**：支持 `720p`、`1080p`、平板横屏（`1280×800`）或自定义 `<宽>x<高>@<DPI>`；提供「省资源 (2核·2G) / 均衡 (3核·2G) / 流畅 (4核·4G)」三档性能预设；存储容量支持 `4–128 GB`（默认 `6 GB`）。
- **GPU 渲染模式**：支持 `自动选择（推荐）`、`硬件加速 (host)`、`兼容模式 (ANGLE)` 与 `软件渲染 (SwiftShader)`。若开启时 `< 10s` 因图形初始化崩溃，系统会自动沿兼容后端回退重试并记住有效模式。
- **网络代理与备注**：支持 `http://` 与 `socks5://`（含账密会在日志与界面自动脱敏为 `***`）；支持填写最多 80 字实例备注。
- **运行模式与启动方式**：默认开启后台无头（`-no-window`）与冷启动（`-no-snapshot`）；可选勾选 **「快速启动（保存快照）」** 加速重启（多占约 1–2 GB 磁盘；硬件/代理/分辨率变更或上次异常退出后会自动执行一次冷启动自愈）。

### 工作台列表、排序与详情栏
- **排序与搜索**：列表顶部支持 `默认排序`、`按名称`、`运行中优先`、`最新创建` 四种排序方式，右侧搜索框支持按**实例名称、备注或 ID** 实时过滤。
- **行内快捷操作**：每行右侧直接提供快捷按钮——已停止实例一键 **「启动」**，运行中/启动中实例一键 **「投屏」**。
- **多选与混合状态处理**：支持复选框、`全选`、`选择 → 仅选运行中`。多选出现分层批量操作条；若选中实例状态混合（例如同时选中运行中与已停止实例），操作按钮显示可用数（如 `投屏 (2/3)`），点击后弹窗确认 **「仅操作可用的 N 台」**。
- **右侧详情栏（4 张卡片）**：
  1. **设备概览**：状态徽章（启动中动态显示已等待秒数，异常悬停/首屏直接展示完整错误与「复制错误」）、轻量分组切换胶囊、主操作按钮（启动 / 投屏 / 静音-有声切换 / 停止）及「更多操作」菜单（编辑、投屏设置、复制 ADB 命令、应用管理、虚拟定位、一键截图、磁盘清理、备份实例、安装 APK、Shell、文件传输、删除）。
  2. **设备配置**：展示镜像、硬件资源、屏幕形态、GPU 渲染、备注、启动方式（快速启动支持「清除快照 / 下次冷启动」）、显示模式、投屏摘要、ADB 序列号与实例 ID。
  3. **网络代理**：展示已保存与当前生效代理（「待重启生效」高亮提醒），说明本地 SOCKS5 桥接仅覆盖 TCP/HTTP 栈（UDP/QUIC 与绕过系统代理的应用需在安卓内使用 VPN 工具）。
  4. **最近运行应用**：通过装包流水线或应用管理拉起应用后自动沉淀，支持一键再次启动。

### 编辑单个实例
在详情栏 **「更多操作 → 编辑」** 或批量条 **「编辑」** 中打开：
- **立即生效**：实例名称与备注。
- **下次启动生效**：分辨率、内存、CPU 核数、GPU 渲染模式、网络代理、运行模式（后台无头 / 自带窗口）与快速启动快照开关。

## 4. 统一应用安装与拖放流水线

无论点击工作台顶栏 **「安装 APK」**、详情栏 **「装包」**、批量菜单 **「工具 → 安装 APK」**，还是直接将文件**拖放**进工作台窗口，均进入同一套安装流水线：

- **支持格式**：单包 `.apk` 与主流分包 `.apks` / `.xapk`（纯 Go 解压并按目标实例运行态 `ro.product.cpu.abilist` 与屏幕 DPI 自动筛选匹配分包后调用 `adb install-multiple`；若含 OBB 数据文件会在确认卡与日志中提示补充路径）。
- **防穿透元素级拖放**：仅在无任何弹窗打开时生效：
  - 将 `.apk` / `.apks` / `.xapk` 拖到**特定实例行**上会高亮该行并锁定为目标实例。
  - 拖到工作台空白区会优先预选当前勾选实例或上次安装目标。
  - 拖入**普通文件**（非安装包）会自动转入「文件传输 → 发送到 Android」待发送队列。
- **确认卡与执行阶段**：
  - 毫秒级离线预检包名与原生库 ABI（若目标实例不兼容 ARM 库或未配置转译会提前预警）。
  - 允许选择**已停止 / 启动中 / 运行中**的多台实例（超 `MaxConcurrent` 上限时提前警告）。
  - 可选勾选 **「装完自动打开应用并投屏」**（单台默认开启，多台默认关闭；仅无头实例会拉起 `scrcpy`，自带窗口模式不重复弹窗）与 **「授予常规运行时权限 (`-g`)」**（默认关闭）。
  - 执行期间在右下角悬浮胶囊展示 4 步进度（启动与引导就绪 + `pm` 探活 → 安装 → 设备侧 `resolve-activity` 解析 Launcher 并启动 → 打开投屏），支持随时取消或通过「停止」按钮打断等待。

## 5. 分组管理与分组协作

- **侧栏内嵌分组树**：工作台左侧导航下方直接展开「全部分组」、各自定义分组与「未分组」，实时显示组内实例数；点击即可切换筛选视图，并支持在侧栏点击分组旁的快速启动按钮。
- **分组协作条**：选中某个自定义分组后，工作台列表上方出现分组协作条，提供：
  - **启动整组**：预检当前空闲并发余量（`MaxConcurrent` 减去当前运行/启动中数量）；若超额会弹窗提示选择「仅启动余量允许的前 N 台」或取消，并以 `1.5s` 间隔错峰启动降低宿主磁盘 I/O 峰值。
  - **停止整组**：一键停止该分组下全部运行中/启动中实例。
  - **分组布局**：直接打开针对该分组作用域的投屏排版弹窗，为不同业务分组保存/恢复各自的命名窗口布局。
- **管理分组与移入**：点击「管理分组」可新建、重命名或删除分组（删除分组仅将成员退回「未分组」，**绝不删除实例或数据**）；勾选实例后可通过批量操作条「移至分组」或详情栏头部胶囊快速调整归属。

## 6. 多窗口投屏排版

打开多台实例的 `scrcpy` 投屏窗口后，点击工作台顶部 **「投屏排版」**（或分组协作条 **「分组布局」**）：

- **排列范围**：可选「当前分组」、「全部已打开投屏」或「仅选中实例」。
- **窗口大小与列数**：支持「当前大小」、预设「小 (`360px`) / 中 (`540px`) / 大 (`720px`)」或「以窗口为基准」；支持显式设置 **「每行窗口数」**（`0` 为自动铺满换行）。
- **记忆窗口位置与自动补位**：
  - 勾选 **「记住各实例窗口位置」** 后，单独关闭并重新投屏时尽量恢复上次关闭前的窗口位置与大小。
  - 勾选 **「新投屏自动补位」** 后，新打开的投屏窗口自动按上次排版规格在目标显示器寻找空位放置，不打乱已有窗口。
- **命名布局快照**：支持按全局或分组保存、一键恢复及删除多套命名布局（存储在 `VirDeckData/config/screen_layout.json`）。
- **平台说明**：Windows（Win32）与 macOS（CoreGraphics + Accessibility API，需在系统设置授予「辅助功能」权限）支持完整的动态枚举、对齐与布局保存/恢复；Linux 环境支持在启动与重开 `scrcpy` 时通过坐标参数（或 CLI `screen -x -y -width -height`）定位。

## 7. 投屏参数与声音控制

投屏编码参数与声音转发采用 **「全局默认 + 单实例覆盖」** 两级体系，修改仅影响 `scrcpy`，**不修改安卓内部屏幕分辨率，也无需重启安卓实例**：

- **参数范围**：帧率 `5–240 FPS`（默认 `60`）、最长边 `320–8192 px`（默认 `1280`）、码率 `1–100 Mbps`（默认 `8`）、声音开关（默认静音）。
- **三档场景预设**：**省资源多开**（15 FPS / 960 px / 2 Mbps）、**均衡日常**（60 FPS / 1280 px / 8 Mbps）、**高清流畅**（60 FPS / 1920 px / 16 Mbps）。
- **快捷声音开关**：详情栏头部主操作区旁提供紧凑 **「静音 / 有声」** 按钮一键切换并自动重开已打开投屏；音频转发采用 `AAC` 编码（需 **Android 11 / API 30 及以上**镜像，且设备内媒体音量未静音）。

## 8. 多设备操作同步

点击工作台顶栏 **「同步操作」** 打开多设备同步控制面板（需至少 2 台运行中实例）：

- **主从配置**：选择 1 台**主控设备**（未开投屏时自动打开主控 `scrcpy` 窗口）与 1 台或多台**被控设备**（被控机**无需打开投屏窗口**，后台无头模式即可同步）。
- **防齐步抖动参数**：可选设置「防齐步微延迟」（`0–300 ms`）与「随机位置微偏移」（`0–10 px`）。
- **实时鼠标捕获与归一化映射（Windows）**：基于非管理员 Win32 `WH_MOUSE_LL` 捕获主控画面区左键按下/移动（~60Hz 节流）/抬起与滚轮，扣除标题栏与黑边后映射至各被控机设备坐标（同分辨率像素级精准，异分辨率自动等比缩放）。拖出画面区、窗口失焦或暂停时自动补发 `ACTION_UP` 防长按卡死。
- **暂停热键、状态条与单台开关**：开启同步后，工作台上方出现醒目的状态条，支持按 **`Ctrl+Alt+P`** 一键暂停/恢复、点击 **「返回 / 主页 / 多任务」** 广播导航键、随时**临时踢出或重新加入**单台被控机，或发送**中英文/链接文本**（全平台通用，通过 `scrcpy` 剪贴板自动同步粘贴）。
- **macOS / Linux 说明**：当前 macOS 与 Linux 端暂不支持全局鼠标捕获，系统会自动显示降级提示，但同步面板与工作台同步条中的**导航键广播与中文文本同步粘贴**仍可正常使用。

## 9. 实用运维工具（定位 / 截图 / 应用管理 / 磁盘与备份）

- **虚拟 GPS 定位**（详情栏「更多操作」或批量条「配置 → 虚拟定位」）：内置北京、上海、东京、纽约、伦敦、新加坡 6 个城市预设，并支持手动输入十进制经纬度批量注入运行中实例。
- **一键无头批量截图**（详情栏「更多操作」或批量条「工具 → 一键截图」）：无需打开投屏窗口，并发调用 `adb exec-out screencap -p` 输出高清 PNG 至 `VirDeckData/screenshots/`。
- **轻量应用管理**（详情栏「更多操作」或单选「工具 → 应用管理」）：查看运行中实例已安装的第三方或全部应用包名，支持关键词搜索及单应用 **启动 / 强停 / 二次确认清数据 / 二次确认卸载**。
- **磁盘清理**（详情栏「更多操作 → 磁盘清理」）：
  - **运行中实例**：在线执行 `adb shell sm fstrim` 整理存储。
  - **已停止实例**：清理可再生的 `cache.img.qcow2`，并自动调用 SDK 内置 `qemu-img convert -O qcow2 -B ...` 压缩 `userdata-qemu.img.qcow2` 与 `sdcard.img.qcow2` 覆盖层镜像（保留 backing-file 关联，绝不破坏数据）。
- **单实例便携备份与还原**：
  - **备份**（详情栏「更多操作 → 备份实例」，仅已停止实例）：将实例配置元数据、`avd.ini` 与 `.avd/` 完整打包为 `.zip`（排除 `.lock` 临时锁文件）。
  - **还原**（表头「选择 → 从备份还原…」或新建弹窗「从备份还原…」）：选择备份 `.zip` 即可在新目录或本机恢复为全新独立实例（自动生成新 ID 并重写路径）。

## 10. 电脑与安卓文件收发

点击左侧导航 **「文件传输」** 进入独立整页视图（也可在工作台拖入普通文件直达）：

- **发送到 Android（支持多台并发）**：左侧选择目标运行中实例与共享存储目标目录（默认 `/sdcard/Download/VirDeck/`），右侧维护待发送队列；每次发送在目标目录下创建带时间戳与唯一后缀的子目录并对重名文件编号防覆盖，发送后自动触发 Android 媒体库扫描刷新相册。

## 12. 命令行工具 (CLI) 参考

`virdeck-cli`（Windows 下为 `virdeck-cli.exe`）与 `VirDeck cli` 共享同一套底层服务与数据目录：

| 命令 | 参数示例 | 说明 |
| :--- | :--- | :--- |
| `env` / `check` | `virdeck-cli env` | 自检数据目录、映射路径、硬件加速、工具路径与已安装镜像 |
| `bootstrap` | `virdeck-cli bootstrap -tool all`<br>`virdeck-cli bootstrap -tool scrcpy -zip ./scrcpy.tar.gz` | 在线下载补齐或从本地压缩包离线导入基础组件 (`all` \| `adb` \| `emulator` \| `scrcpy`) |
| `images` / `catalog` | `virdeck-cli images`<br>`virdeck-cli images -sync`<br>`virdeck-cli images -download <包ID>`<br>`virdeck-cli images -import <包ID> -zip <路径>`<br>`virdeck-cli images -rm <包ID>` | 查看镜像目录、同步官方源、在线下载、离线导入或删除已安装镜像 |

| `delete` / `rm` | `virdeck-cli delete acc_03` | 停止并彻底删除指定实例及其磁盘文件 |

## 13. 数据目录结构与迁移

默认情况下，便携运行的所有数据保存在可执行文件同级的 `VirDeckData/` 目录（macOS 从 `VirDeck.app` 启动时默认位于 `~/Library/Application Support/VirDeck`）：

```text
VirDeckData/
├── config/             # 用户配置：settings.json、instances.json、images_catalog.json、groups.json、screen_layout.json
├── .android/           # 隔离的 ANDROID_USER_HOME（存放 adbkey 等，属主私有权限）
├── avd/                # 虚拟机实例目录（.ini 与 .avd/ 独立磁盘数据）
├── sdk/                # 免安装 SDK 根目录（emulator/、platform-tools/、platforms/、system-images/）
├── scrcpy/             # scrcpy 投屏与控制通道组件目录
├── downloads/          # 下载包缓存与断点续传元数据（.zip、.tar.gz、.part、.meta）
├── screenshots/        # 一键无头批量截图默认导出目录（PNG）
└── backups/            # 单实例便携备份默认导出目录（.zip）
```

- **配置文件说明**：
  - `config/settings.json`：全局设置（下载代理、最大并发数、ADB 端口、自动删包、投屏默认参数与单实例覆盖、排版偏好、许可协议确认状态）
  - `config/instances.json`：实例注册表（原子写临时文件再重命名，含 ABI 探测缓存与最近运行应用）
  - `config/groups.json`：实例分组定义与成员映射
  - `config/screen_layout.json`：多窗口投屏坐标、实例记忆位置与分组命名布局快照
  - `config/images_catalog.json`：系统镜像目录缓存、收藏与备注
- **迁移方法**：确保所有安卓实例已停止且 VirDeck 已退出后，直接将程序与数据目录整体移动或复制到新位置即可。启动时程序会自动扫描 `avd/*.ini` 并将 `path=` 与 `path.rel=` 修正为当前路径。
- **环境变量覆盖**：可通过 `VIRDECK_DATA_DIR` 指定数据目录位置，通过 `VIRDECK_REGISTRY` 指定实例注册表路径。

## 14. 常见问题排查 (FAQ)

1. **启动实例报错硬件加速（WHPX / Hypervisor.framework / KVM）不可用？**
   - **Windows**：以管理员身份运行 `dism.exe /online /enable-feature /featurename:HypervisorPlatform /all`，完成后**重启电脑**，并确认 BIOS 已开启虚拟化。
   - **macOS**：确认 `sysctl -n kern.hv_support` 输出为 `1`，并使用与芯片架构匹配的系统镜像（Apple Silicon 使用 `arm64-v8a`，Intel Mac 使用 `x86_64`）。
   - **Linux**：确认已加载 `kvm` 模块且当前用户对 `/dev/kvm` 有读写权限（`sudo usermod -aG kvm $USER` 后重新登录）。
2. **Windows 下放在中文目录无法启动模拟器？**
   - VirDeck 会自动尝试 `8.3` 短路径或 NTFS 目录联接；若系统盘禁用 8.3 短路径且权限受限，可在启动弹窗或「镜像与环境 → 运行环境」点击 **「一键改用纯英文数据目录」** 切换路径。
3. **macOS 下点击「投屏排版」提示需要辅助功能权限？**
   - 打开「系统设置 → 隐私与安全性 → 辅助功能」，勾选 `VirDeck`（若从终端运行则勾选对应终端应用），授权后重试。
4. **开启了投屏声音但听不到声音？**
   - 请确认：(1) 实例使用的是 **Android 11 (API 30) 或更高版本**镜像；(2) 安卓系统内媒体音量未静音；(3) 已通过详情栏「静音 / 有声」按钮或「保存并重新投屏」重开投屏窗口。
5. **配置了 `socks5://` 代理但部分 App 或游戏 UDP 流量未走代理？**
   - Android Emulator 原生仅支持 `-http-proxy`，VirDeck 通过宿主机本地 `127.0.0.1` HTTP CONNECT → SOCKS5 桥接转发 TCP/HTTP 流量；UDP/QUIC 或主动绕过系统代理的应用仍需在安卓内使用 VPN 类客户端。
6. **修改了实例代理、GPU 或内存/CPU，为什么没有立即变化？**
   - 模拟器硬件参数与代理均为进程启动参数，运行中修改后会标注「待重启生效」，将该实例「停止」后再「启动」即可应用（开启快速启动时系统会自动附带冷启动参数确保新配置生效）。
