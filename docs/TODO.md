## 下一阶段：基础功能

### 1. 省资源与投屏参数

- [x] 在设置界面集中管理全局投屏帧率、清晰度、视频码率和声音开关。
- [x] 默认所有实例跟随全局设置；实例允许切换为单独配置，并可恢复跟随全局。声音也支持相同的全局/实例控制。
- [x] 清晰度控制投屏编码尺寸，不修改安卓内部屏幕分辨率；本轮不通过削减 CPU、内存或暂停应用来省资源。
- [x] 核查 emulator 当前音频启动参数及 scrcpy 音频转发链路，确保开启声音后实际可听，不能只添加界面开关。
- [x] 明确参数生效时机及必要的投屏重开提示，优先不重启安卓实例。
- [x] 默认参数继续放编译期 config/defaults.json；用户全局设置和实例覆盖保存在 VirDeckData 内。先前举例的 15 FPS、960/1024、2 Mbps 不视为已确认默认值。

### 2. 补齐不明显的失败原因

- [x] 查找操作等待、没有反馈或丢失底层错误的环节，补充当前阶段、合理超时以及进程退出/失败原因。
- [x] 优先覆盖启动、ADB、环境检测、投屏和工具/镜像处理中的无反馈路径；已有明确错误直接复用，不额外重复翻译。
- [x] 将可定位问题的信息接入现有任务与日志；操作失败时界面能看到失败状态和日志入口，避免用户无期限等待。
- [x] 作为相关操作的错误反馈补强，不单独扩成全量诊断中心、错误翻译库或自动修复系统。

### 3. 基础文件收发

- [x] 提供电脑向安卓实例发送文件、安卓实例向电脑接收/导出文件的便捷入口。
- [x] 复用现有操作系统文件管理、文件选择能力及 ADB 传输；安卓端继续使用现有文件管理器，不自建完整文件浏览器。
- [x] 覆盖文件选择、目标/导出目录选择、结果与错误提示，处理中文及带空格的文件名和同名冲突。
- [x] 不扩展为实时双向同步、目录监听或共享盘系统。

### 4. 基础分组

- [x] 支持创建、重命名、删除分组，将实例分配或移动到分组，保留未分组项。
- [x] 按分组筛选实例，并复用现有批量启动、停止、投屏等操作。
- [x] 删除分组不删除实例；分组关系使用稳定实例 ID 保存。
- [x] 本轮仅做基础分组，不附带标签、颜色、复杂层级或额外应用管理功能。
